`LocalWorld` now stores event and step files one directory per run (`events/<runId>/`, `steps/<runId>/`), matching `@workflow/world-local`, so reading a run lists only that run's files. A data directory holding only old flat-layout event and step files is deleted on startup, as `@workflow/world-local` does; one that mixes both layouts or holds unknown `.json` files in `events/` or `steps/` raises `DataDirLayoutError` and is left untouched. Use a `workflow` CLI release with the same layout to inspect runs.
