Recover from network interruptions while streaming process output. `run_process` no longer fails or reruns the command when its connection drops after the process starts; it resumes the output from the logs endpoint and waits for the exit code. If the sandbox stops after the process starts, `run_process` raises `SandboxStreamError` with the lifecycle code instead of resuming the sandbox and running the command again. Process `stdout`/`stderr` readers reconnect without duplicating output, including when a stream ends partway through a record or the API reports `sandbox_stream_closed`, and process waits retry transient connection failures, rate limits, and server errors.
